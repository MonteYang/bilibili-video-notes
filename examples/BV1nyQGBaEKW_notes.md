# 什么是Harness？不就是Agent的Infra嘛

- UP主：ZOMI酱
- 时长：14分08秒
- 链接：https://www.bilibili.com/video/BV1nyQGBaEKW

## 核心要点

### 1. 一条演进线：Prompt 工程 → 上下文工程 → Harness 工程
- 2022-2024 年流行提示词工程，关心"怎么问模型"：角色设定（"我是一个IT从业者，请帮我写代码"）+ few-shot、CoT 这类单点技巧 [02:33]
- 2025 年模型上下文窗口拉到 64k/128k，重心变成"给模型看什么"：文档、历史对话还是工程信息，于是出现 RAG、向量库、记忆建模 [03:30]
- 2026 年 3-4 月起，Harness 工程出现：优化对象从模型变成 Agent 的运行环境 [04:04]

### 2. ZOMI 的核心观点：Harness 就是 Agent 的 Infra
- 不认同"Harness 是 Agent 的操作系统"这个比喻，他的定义：Harness 是对 Agent 周边和运行环境进行约束的基础设施 [01:51]
- 一句话总结：Agent = 大模型 + Harness [09:47]

### 3. Harness 的四大支柱
- **上下文工厂**：负责给 Agent 准备"喂"给模型的内容 [10:17]
- **架构约束**：Agent 自己不知道边界在哪，要用类似 AGENTS.md 的规范告诉它什么能做、什么不能做 [10:33]
- **反馈循环**：Agent 做错了无法自我修复，需要规划→生成→验证的循环，多 Agent 之间互相验证 [11:45]
- **熵管理**：执行过程会产生垃圾信息和碎片，要清理状态，否则上下文越来越长 [11:58]

### 4. 对普通使用者的判断：不需要了解
- 观点很直接：不做 Agent 框架开发的人，Harness 根本不重要，就像普通人不需要懂 RESTful API 的设计一样 [12:58]
- 聊天框用户"用就完了"，这些规范是给工程师的 [10:53]

### 5. 真正决定 Agent 能力的是什么
- 不是 Harness——它只是约束和规范；核心是大模型本身的智能，以及 Memory（记忆）[13:21]
- Harness 居于大模型和 Memory 之间，是一套约束性的 Infra 体系 [13:47]

## 关键概念解释

| 概念 | 解释（按视频口径） |
|------|------|
| Harness | 围绕 Agent 构建的运行环境与约束规范，即 Agent 的 Infra；当前指软件，UP主认为未来会延伸到硬件 |
| Prompt 工程 | 大模型早期（2022-2024）的输入优化：角色设定 + 单点技巧（few-shot、CoT） |
| 上下文工程 | 2025 年起：决定给模型投喂什么信息，催生 RAG、向量库、长期/短期记忆区分 |
| Agent 表现不好的根因 | "不是模型不够聪明，是缺少可靠的执行环境"：不知道看什么、做错了怎么改、什么时候该停 [09:06] |

## 实践建议

- 不写 Agent 框架的话，不用刻意学 Harness 的四大支柱，知道概念即可
- 在写 Agent 代码的话，四大支柱（上下文/架构/反馈/熵管理）可以作为架构评审的检查清单
- UP主预测：模型能力之外，Memory 是下一个核心战场
